# 📊 Obsidian Note Analyzer + Telegram Bot

**Obsidian Note Analyzer** — это многоконтейнерное приложение, которое анализирует ваше хранилище Obsidian (папку с .md‑файлами) и предоставляет:

1. **Веб‑интерфейс** (Flask + Nginx) с дашбордом статистики: количество заметок, популярные теги, внутренние ссылки, частотность слов.
2. **Telegram‑бота** (aiogram), который:
   - периодически проверяет хранилище и присылает дайджест новых или изменённых заметок;
   - позволяет просматривать список заметок (`/list`) и их содержимое (`/show`);
   - даёт возможность добавлять заметки в ежедневный файл через команду `/add`.

Проект демонстрирует:
- Использование **MCP‑подхода** (Model Context Protocol) для взаимодействия с файловой системой.
- Применение принципов **SOLID** (особенно **Single Responsibility** и **Dependency Inversion**).
- Контейнеризацию с помощью **Podman** (совместим с Docker).
- Автоматическое обновление данных при изменении заметок.

**Сервисы (контейнеры):**
- **backend** – Flask‑приложение, предоставляющее API для анализа заметок. Использует `MCPAdapter` (адаптер к файловой системе) и `NoteAnalyzer` для вычисления статистики.
- **frontend** – Nginx, отдающий статическую HTML‑страницу и проксирующий запросы к `/api/*` на backend.
- **telegram-bot** – асинхронный бот на aiogram, который каждые `CHECK_INTERVAL` секунд сканирует хранилище и отправляет дайджест в указанный чат Telegram, а также обрабатывает команды пользователя.

---

## 🛠 Принципы SOLID в коде

- **SRP (Single Responsibility)**:
  - `config.py` – только конфигурация.
  - `mcp_adapter.py` – только взаимодействие с хранилищем.
  - `analyzer.py` – только анализ текста и вычисление статистики.
  - `app.py` – только маршруты HTTP.
  - `bot.py` – только логика бота и отправка сообщений.
- **DIP (Dependency Inversion)**:
  - Backend зависит от абстракции `MCPAdapter`, а не от конкретной реализации. Мы легко можем заменить файловый адаптер на адаптер к удалённому API (например, Google Drive).

## 🚀 Установка и запуск (без .bat/.ps1 скриптов)

### 1. Клонирование репозитория
```bash
git clone <url-репозитория>
cd obsidian-analyzer
2. Создание файла .env
Скопируйте .env.example в .env и отредактируйте его:

bash
cp .env.example .env   # на Windows: copy .env.example .env
Минимальное содержимое .env:

env
# Путь к хранилищу Obsidian (для теста можно использовать ./test_vault)

# Настройки OpenAI (заглушка, если не используете AI)

OPENAI_API_BASE=https://proxypi.ru/v1
OPENAI_API_KEY=sk-dummy-key

# Настройки Telegram-бота (обязательно для работы бота)
BOT_TOKEN=ваш_токен_от_BotFather

CHECK_INTERVAL=60   # интервал проверки в секундах (можно поставить 3600 для продакшена)
3. Запуск контейнеров (через podman-compose)
bash
# Сборка и запуск всех сервисов в фоновом режиме
podman-compose up --build -d
Если используется Docker, замените podman-compose на docker-compose.

4. Проверка работы
Веб‑интерфейс будет доступен по адресу: http://localhost:8080

Backend API можно проверить: http://localhost:5000/api/analyze

5. Остановка контейнеров
bash
podman-compose down
6. Просмотр логов
bash
# Логи всех сервисов
podman-compose logs -f

# Логи только бота
podman logs obsidian-telegram-bot
🤖 Настройка Telegram-бота (подробно)
Получение токена
Напишите @BotFather в Telegram.

Используйте команду /newbot, следуйте инструкциям.

Скопируйте полученный токен в переменную BOT_TOKEN в .env.

Получение CHAT_ID
Для личного чата: напишите боту любое сообщение, затем выполните в браузере:

text
https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates
В ответе найдите chat → id (положительное число).

Для группы: добавьте бота в группу, отправьте любое сообщение, затем выполните тот же запрос – в ответе появится chat → id (отрицательное число, начинается с -100).

Вставьте полученное значение в CHAT_ID в файле .env.

После обновления .env перезапустите контейнеры:

bash
podman-compose down && podman-compose up -d
📊 Использование веб‑интерфейса
Откройте в браузере http://localhost:8080:

Общая статистика – количество заметок, ежедневных заметок, уникальных тегов, уникальных связей.

Популярные теги – облако тегов с частотой.

Внутренние связи – таблица, показывающая, сколько раз каждая заметка упоминается в других.

Частота слов – топ‑20 слов (исключая служебные).

Поиск – по кнопке «🔍 Поиск» можно искать текст по всем заметкам.

Все данные обновляются при нажатии кнопки «🔄 Обновить» или автоматически при загрузке страницы.

📬 Команды Telegram-бота
Команда	Описание
/start	Приветствие
/help	Справка по командам
/ping	Проверка работоспособности бота
/list	Показать список всех заметок (имена и заголовки)
/show <имя_файла>	Показать содержимое конкретной заметки (например, /show README.md). Если не указать аргумент – показывает список.
/add <текст>	Добавить новую заметку в ежедневный файл (папка Daily/). Пример: /add Сегодня изучил MCP
Бот также автоматически присылает дайджест новых или изменённых заметок каждые CHECK_INTERVAL секунд.

🔧 Возможные проблемы и их решение
Проблема	Решение
Не скачиваются образы (EOF)	Настройте зеркало для Docker Hub в /etc/containers/registries.conf (добавьте dockerhub.timeweb.cloud).
Бот не отправляет сообщения	Проверьте BOT_TOKEN и CHAT_ID в .env. Убедитесь, что бот добавлен в чат и имеет права на отправку сообщений.
Команды /add, /list, /show не работают	Убедитесь, что вы обновили telegram_bot/bot.py до версии с этими командами и пересобрали контейнер: podman-compose build --no-cache telegram-bot && podman-compose up -d.
Веб‑интерфейс показывает старые данные	Нажмите «🔄 Обновить». Если данные не обновляются – проверьте, что папка с заметками смонтирована правильно (в docker-compose.yml указан корректный путь).
Ошибка записи при /add	Убедитесь, что в docker-compose.yml для telegram-bot монтирование без :ro (только /vault, не /vault:ro). Перезапустите контейнеры.
