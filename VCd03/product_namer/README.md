# Product Namer Agent

Автономный агент для генерации 5 вариантов названий продукта на основе содержимого веб-страницы. Агент загружает HTML по URL, извлекает текст, отправляет запрос к большой языковой модели (LLM) через Proxy API и возвращает список названий с пояснениями.

Проект разработан с соблюдением принципов **Single Responsibility** и **Dependency Inversion**, имеет полную типизацию, логирование, обработку ошибок с повторными попытками и модульные тесты.

---

## 📋 Функциональность

- Загрузка HTML-страницы по указанному URL.
- Извлечение чистого текста (удаление тегов, скриптов, стилей) с помощью BeautifulSoup.
- Формирование системного промпта с ролью "креативный маркетолог".
- Отправка запроса к LLM через ProxyAPI (совместим с OpenAI API).
- Получение ответа в формате JSON с массивом из 5 объектов (название + причина).
- Обработка ошибок сети и API с автоматическими повторными попытками (до 3 раз).
- Возврат структурированного результата в виде списка словарей.

---

## 🚀 Требования

- Python 3.10 или выше
- API-ключ для сервиса ProxyAPI (например, [proxyapi.ru](https://proxyapi.ru) или другой прокси)
- Установленные зависимости (см. `requirements.txt`)

🛠 Принципы проектирования
SRP (Single Responsibility Principle):

openai_module.py отвечает исключительно за взаимодействие с LLM API.

agent.py содержит бизнес-логику: загрузку страницы, парсинг, формирование промптов, обработку ответа.

Тесты изолированы и тестируют отдельные компоненты.

DIP (Dependency Inversion Principle):

Агент зависит от абстракции LLMClient, а не от конкретной реализации. Это позволяет легко подменять клиент (например, для тестов) и расширять функциональность.

Обработка ошибок и устойчивость:

Используется библиотека tenacity для автоматических повторных попыток при сетевых сбоях.

Логирование с разными уровнями (DEBUG, INFO, WARNING, ERROR) помогает диагностировать проблемы.

Конфиденциальные данные (API-ключи) не выводятся в логи.

Типизация:

Весь код аннотирован типами, что облегчает статическую проверку (mypy) и улучшает читаемость.

🔧 Устранение проблем
Ошибка соединения (ConnectionError, getaddrinfo failed) – проверьте правильность BASE_URL в .env, доступность интернета и корректность API-ключа.

Ошибка импорта модулей – убедитесь, что виртуальное окружение активировано и все зависимости установлены.

Прокси-сервер – если у вас настроен системный прокси, код принудительно отключает его (через обнуление переменных окружения). При необходимости вы можете явно задать прокси в коде.
